# ممیزی و اصلاح سئوی پاداش — ۴ نوامبر ۲۰۲۶

## محدوده و وضعیت پیش از تغییر

پروژه Next.js 16.3.4 App Router، React 19 و TypeScript است. دامنهٔ مرجع مطابق تصمیم مالک `https://padashco.netlify.app` باقی می‌ماند. این نوبت فقط metadata، JSON-LD، sitemap و آزمون‌های مربوط را تغییر می‌دهد؛ متن قابل مشاهده، CSS، تصاویر، URLها، API، احراز هویت و منطق برنامه جزو محدوده نیستند.

وضعیت Git و SHA-256 تعداد ۳۰۱ فایل پیش از کار در پوشهٔ نادیده‌گرفته‌شدهٔ `.sites-runtime/seo-audit-2026-11-04` ثبت شد. اطلاعات محرمانه، `.env`، داده‌های درخواست‌ها و Git از این ثبت کنار گذاشته شدند. تغییرات قبلی کاتالوگ، محاسبه‌گر و لوگو حفظ می‌شوند و جزو تغییرات این ممیزی حساب نمی‌شوند.

خروجی HTML تمام ۲۱ URL موجود در sitemap پیش از تغییر ثبت شد: صفحهٔ اصلی، فهرست محصولات، ۱۲ صفحهٔ محصول، فهرست راهنماها، ۴ مقاله، محاسبه‌گر و فهرست اخبار. خبر منتشرشده‌ای در این بررسی محلی وجود نداشت. همه پاسخ ۲۰۰، یک H1، عنوان و توضیح یکتا داشتند. robots اجازهٔ خزیدن صفحات عمومی را می‌داد و API را مسدود می‌کرد. canonicalها به دامنهٔ تأییدشده اشاره می‌کردند. مشکلاتی مثل عنوان تکراری، نبود description یا فقدان H1 در این نمونه پیدا نشد.

## محدودیت‌های ارزیابی

محتوا، metadata و پاسخ HTTP در اجرای محلی بررسی می‌شوند. امتیاز واقعی LCP، INP و CLS از HTML به دست نمی‌آید؛ بدون دادهٔ CrUX، Search Console یا اجرای مرورگر، عدد یا امتیاز قبولی اعلام نمی‌شود. انتشار روی Netlify و دسترسی Search Console جزو نتیجهٔ این تغییر محلی محسوب نمی‌شوند.

## نتیجهٔ اصلاحات

- عنوان و توضیح ۱۲ صفحهٔ محصول متناسب با نام محصول، مشخصات قابل استعلام و قصد خرید/استعلام تنظیم شد. توضیحات از محتوای واقعی همان صفحه استفاده می‌کنند؛ قیمت، تخفیف، موجودی، تضمین یا نمایندگی اضافه نشده است.
- فقط عنوان SEO چهار مقاله کوتاه‌تر و موضوعی‌تر شد. H1، توضیح قابل مشاهده و محتوای مقاله‌ها عیناً حفظ شدند.
- WebSite با نام کوتاه واقعی «پاداش» تکمیل شد. Organization، شماره‌ها و ترتیب مدیران حفظ شدند.
- فهرست محصولات اکنون CollectionPage متصل به ItemList دوازده‌تایی و BreadcrumbList دارد. این داده‌ها فقط JSON-LD هستند و مسیر یا لینک قابل مشاهده‌ای به صفحه اضافه نشده است.
- برای شش صفحه دارای عکس محصول، primaryImageOfPage از همان تصویر اول گالری معرفی شد. تصاویر تغییر نکردند.
- sitemap اکنون ۱۹ تصویر موجود محصول را هم معرفی می‌کند. انتظار برای اخبار به ۲٫۵ ثانیه محدود شده است؛ در خطا یا کندی سرویس اخبار، ۲۱ URL ثابت و تصاویر محصولات باقی می‌مانند. درخواست خواندن اخبار در این حالت ممکن است در پس‌زمینهٔ همان اجرای سرور ادامه یابد، اما پاسخ sitemap منتظر تکرارهای طولانی آن نمی‌ماند. خبر منتشرنشده، صفحهٔ مدیریت، رسید، API و پارامترهای ابزار در sitemap نیستند. lastmod فقط برای تاریخ‌های واقعی موجود درج می‌شود؛ زمان هر بازدید به‌عنوان آخرین تغییر ثبت نشده است.
- robots.txt تغییر نکرد؛ تنظیم موجود به صفحات عمومی اجازهٔ خزیدن می‌دهد. noindex صفحات خصوصی و ۴۰۴، canonical صفحات و پارامترهای محاسبه‌گر آزمایش شدند. تنظیمات streaming metadata پیش‌فرض Next.js تغییر نکردند؛ طبق مستند رسمی این رفتار با Googlebot سازگار است و غیرفعال‌کردن بی‌دلیل آن می‌تواند زمان پاسخ را بیشتر کند.

### تصمیم دربارهٔ Product و Article

صفحات موجود معرفی خانوادهٔ محصول برای استعلام‌اند و هنوز مدل نهایی، پیشنهاد مالی، نظر یا امتیاز واقعی منتشرشده ندارند. طبق الزامات رسمی Product snippets، افزودن Product بدون offers/review/aggregateRating آن‌ها را واجد Rich Result نمی‌کند. WebPage و ItemList حفظ و تکمیل شدند؛ صفر به جای قیمت و نظر ساختگی درج نشد. افزودن Product/Offer به زمانی موکول است که محصول واقعی و دادهٔ لازم قابل ارائه باشد.

Article و BreadcrumbList مقاله‌ها و اخبار از قبل وجود داشتند و از نظر ساختار JSON، عنوان واقعی، تاریخ انتشار/تغییر و اطلاعات ناشر بررسی شدند. Organization به جای LocalBusiness استفاده می‌شود، زیرا نشانی فیزیکی تأییدشده‌ای در پروژه وجود ندارد. هیچ سابقه، مدرک یا مکان ساختگی اضافه نشده است. آزمون داخلی جای تأیید زنده در Rich Results Test یا Schema Markup Validator را نمی‌گیرد و تأیید آن سرویس‌ها ادعا نشده است.

اولویت تجاری با صفحهٔ اصلی، صفحات عایق‌های اصلی و ابزار متره است. اولویت‌های واقعی بعد از دریافت Impression، Click، CTR و عبارت‌های جست‌وجوی واقعی بازبینی می‌شوند؛ انتخاب فعلی به معنی اثبات حجم ترافیک نیست.

پیشنهادهای نیازمند تأیید مالک، بدون اجرا در این نوبت:

1. تولید راهنمای مستقل برای انتخاب فویل/متالایز، جنس و چشمهٔ توری، و ابعاد/گرماژ کارتن‌پلاست با دیتاشیت‌های واقعی؛ سپس لینک متقابل راهنما و محصول.
2. تکمیل مشخصات محصولات با مدل‌های واقعی، ابعاد بسته‌بندی، مدارک فنی و تصاویر همان مدل. متن خانواده به مشخصات قطعی یک SKU تبدیل نشده است.
3. ساخت صفحهٔ مستقل برای دسته‌های مهم فقط با محتوای متمایز و نیاز واقعی. فیلترهای فعلی به صفحه‌های کم‌محتوا و تکراری تبدیل نشوند.
4. بررسی هم‌پوشانی قصد جست‌وجوی صفحهٔ خانواده و زیرگروه‌ها با دادهٔ Search Console؛ ادغام، canonical بین دو محصول یا redirect بدون تحلیل و تأیید انجام نشود.
5. انتشار اخبار واقعی، معرفی پروژه‌های مجاز و پیوندهای واقعی از کانال‌ها و همکاران؛ بدون خرید لینک اسپم یا صفحات جدا برای غلط‌های تایپی نام برند.

فونت محلی، `next/image`، ابعاد مشخص تصاویر و بارگذاری اولویت‌دار تصویر اصلی موجودند و حفظ شدند. لوگوی PNG فعلی ۱٬۶۳۹٬۲۳۶ بایت است؛ استفاده از خروجی اختصاصی سبک‌تر برای آیکون و تصویر اشتراک‌گذاری می‌تواند بررسی شود. تصویر داخل صفحه از مسیر بهینه‌سازی Next.js ارائه می‌شود، بنابراین اندازهٔ فایل اصلی به‌تنهایی زمان LCP را تعیین نمی‌کند. فایل قدیمی hero در صفحهٔ فعلی ارجاعی ندارد؛ صرف وجود آن به معنی افت سرعت بارگذاری نیست. هیچ فایل تصویری، فونت، CSS، انیمیشن یا کامپوننتی برای سرعت تغییر نکرد.

## پس از انتشار و نیازمندی‌های Search Console

1. نسخهٔ اصلاح‌شده روی همان پروژهٔ Netlify منتشر شود؛ انتشار در این نوبت انجام نشده است.
2. مالک در Search Console، URL-prefix property برای `https://padashco.netlify.app/` را تأیید کند. اگر روش meta tag انتخاب شد، مقدار `content` در `GOOGLE_SITE_VERIFICATION` قرار گیرد و دوباره build/deploy انجام شود. این قابلیت از قبل موجود است.
3. sitemap به نشانی `https://padashco.netlify.app/sitemap.xml` ارسال شود. صفحهٔ اصلی، فهرست، یک محصول، یک مقاله و یک خبر واقعی با URL Inspection بررسی شوند.
4. JSON-LD نسخهٔ منتشرشده با Rich Results Test و Schema Markup Validator بررسی شود. نبود Product Rich Result برای خانوادهٔ فاقد پیشنهاد فروش/نظر، با دادهٔ جعلی رفع نشود.
5. پس از جمع‌شدن دادهٔ کافی، queryهای برند و محصول، CTR، وضعیت ایندکس، canonical انتخابی گوگل و Core Web Vitals بررسی شوند. درخواست مجدد ایندکس یا تغییر کد، تضمین رتبه یا نمایش در گوگل نیست.

ثبت hash فایل‌ها یک فایل تولیدی نادیده‌گرفته‌شدهٔ `tsconfig.tsbuildinfo` را نیز نشان می‌دهد که با build/typecheck بازتولید شده است؛ این فایل تغییر منبع یا تغییر طراحی نیست و در Git وارد نمی‌شود. فایل‌های جدید این نوبت فقط متادیتا، آزمون SEO و گزارش ممیزی‌اند.
